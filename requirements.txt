# Exact-pinned, not a range: keras 3.x is versioned independently from
# tensorflow (a separate top-level package tensorflow depends on), so a range
# like ">=2.16,<2.17" still lets pip resolve a *different* keras minor/patch
# per install -- which is exactly what happened between this Windows dev
# machine and Render's Linux container, and Keras 3's initializer config
# format changed between those resolved versions (GlorotUniform gained
# input_axes/output_axes), breaking cross-environment model reload with a
# `.h5` saved by one and loaded by the other. Pinning both packages exactly
# keeps every environment bit-for-bit identical.
